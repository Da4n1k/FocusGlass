# Отчёт: нативное размытие и частицы на Linux

> **Уточнение приёмки основной сессии:** первоначально пользователь не видел
> эффекта на физическом выходе KDE/NVIDIA, несмотря на рост счётчика кадров.
> После установки диагностической сборки под отдельным именем пользователь
> подтвердил: «заблюрились окна терминалов». Однократный GPU-probe показал
> `glError: 0`, `protectedChanged: 0`, `unprotectedChanged: 203723` на
> NVIDIA RTX 3050, 1920×1080. [Результат](evidence/linux-effects/hardware-diagnostics.json).
> Точная причина неудачи первой загрузки не установлена. Отдельное имя исключает
> повторное использование Qt старой загруженной библиотеки; это возможное
> объяснение, а не доказанный диагноз. Видимый самостоятельный тест подтверждён;
> включение через интерфейс/ЭЭГ в этой основной сессии проверяется отдельно.

## Результат и границы проверки

### Исправление слабого эффекта и включения по порогу

После пользовательской проверки обнаружены радиус 0 в сохранённых настройках,
скрытая задержка размытия до 3,08 с и постоянное подмешивание резкой сцены.
Исправлено:

- Linux сравнивает сглаженную метрику с эффективным порогом напрямую,
  учитывает инверсию и калибровку, без дополнительного условия opacity > 0,01.
- Эффект начинает проявляться сразу; частицы не задерживают обратную связь.
- При установившемся состоянии резкая сцена полностью заменена размытым
  изображением. Плавное смешивание осталось только на включении/выключении.
- Для сильного размытия добавлено последовательное 2× уменьшение перед Gaussian
  проходами, чтобы большие радиусы не создавали резких повторных контуров.
- Новый диапазон 0–16 px, стандартное значение 8 px. Превью использует выбранную
  силу, а при нулевой — проверочные 8 px. Нулевой радиус не изменяется молча:
  он явно помечен, есть кнопка включения.
- Production TypeScript engine/policy → настоящий Rust worker → GPU проверен
  на значениях ниже, на границе, выше порога и в обоих случаях инверсии.

В тесте X11 видимый эффект появился за **0,442 с**, без ожидания трёхсекундной
волны. В KWin/NVIDIA энергия резких границ снизилась с **286060 до 25824**,
защищённые отсчёты не изменились, ошибок OpenGL нет.
Свежие результаты:
[KWin](evidence/linux-effects/threshold-fix-kwin-results.json),
[X11](evidence/linux-effects/threshold-fix-native-results.json),
[Fly, 0,430 с](evidence/linux-effects/threshold-fix-fly-results.json),
[кадр Fly с усиленным эффектом](evidence/linux-effects/threshold-fix-fly-result.png).
Ниже сохранён также исторический отчёт первой версии с более слабым смешиванием.
Для новой пользовательской проверки требуется загрузка новой сборки плагина;
старый уже загруженный код сам не обновляется после пересборки файлов.

Реализованы и проверены **два настоящих бэкенда**, а не CSS-имитация:

| Окружение | Что реально запускалось | Результат |
|---|---|---|
| KDE / Wayland | Плагин внутри отдельного вложенного KWin 6.8.3, настоящие Wayland-окна | Размытие работает; защищённая область не меняется; превью очищается |
| X11 / Fly | Официальный `fly-wm 2.43.9+ci12` из Astra Common, Xvfb + picom, изолированный HOME | Fly управляет окнами; чужое окно размывается; управление и док остаются чёткими; мышь и клавиатура проходят |
| X11 без WM | Xvfb + picom | Те же проверки проходят |

**Это не испытание полной Astra SE и не подтверждение всех версий Fly/KWin.**
Fly проверялся как настоящий оконный менеджер из официальных пакетов, но на
Arch-хосте, с picom, а не в сертифицированной Astra SE с PARSEC. На целевой
машине остаются проверки её GPU, композитора, политик захвата и библиотек.

Текущий системный KWin пользователя не заменялся и не перезапускался.
Для включения нового GPU-бэкенда в основной KDE-сессии нужно установить и
загрузить плагин. Без него приложение использует прежний ограниченный
Wayland-fallback. Инструкция: [native/README.md](../native/README.md).

## Как сделано на Wayland

Обычное прозрачное окно Wayland не имеет доступа к пикселям рабочего стола.
Общий `ext-background-effect` также не даёт приложению контролировать радиус.
Поэтому регулируемый эффект реализован **внутри KWin**:

1. После отрисовки сцены плагин копирует её render target в отдельную GPU-текстуру.
2. Общий OpenGL-рендерер выполняет горизонтальный и вертикальный проходы
   Gaussian blur на уменьшенных буферах.
3. Исходная и размытая сцены смешиваются с плавной силой эффекта; поверх
   рисуются белые частицы.
4. Прямоугольники окон контролирующего процесса и dock-окон исключаются
   через `discard`. PID берётся из `SO_PEERCRED`, а не из присланного JSON.
5. Сцена перерисовывается полностью при активном эффекте: накопленного
   размытия из предыдущего кадра нет. Во время блокировки экрана эффект не рисуется.

В production **нет чтения изображения на CPU**, ScreenCast Portal или захвата
экрана вместе с собственным оверлеем. Эффект не создаёт input-окна и не меняет
фокус клавиатуры.

Плагин использует внутренний API KWin: его необходимо собирать под точную
версию целевого KWin. Поддержка KDE 5 этой реализацией не заявляется.

## Как сделано на X11 / Fly

Отдельный `focusglass-x11` сохраняет существующий WM и композитор:

1. XComposite предоставляет перенаправленные pixmap-ы отдельных окон.
2. В порядке стека окон XRender собирает изображение сцены. Собственное
   окно эффекта явно исключено — итоговый экран не захватывается рекурсивно.
3. До чтения на CPU изображение уменьшается сервером X в четыре раза по
   каждой оси: передаётся в 16 раз меньше пикселей.
4. Уменьшенная сцена загружается в GPU; далее применяется тот же рендерер,
   что и в KWin. При активности запрашивается обновление примерно каждые 33 мс.
5. Результат выводится в прозрачное окно без рамки и фокуса с пустой
   XFixes input shape. Собственные окна и доки остаются прозрачными участками
   этого окна, поэтому под ними виден исходный чёткий интерфейс.

В покое захват и рисование не выполняются. Требуется работающий compositing
manager. В тестах Fly использовался picom; проверка собственного композитора
конкретной поставки Astra остаётся отдельной приёмкой.

Это не точная реконструкция всех эффектов системного композитора:
специфические тени, color management и некоторые реализации обоев могут
отличаться. Исключения прямоугольные, а не попиксельные маски перекрытий.

## Интеграция с FocusGlass

- Движок ЭЭГ, калибровка и Windows-реализация не заменены.
- Новый эффект используется в режиме **«Блюр по порогу»**. Он следует
  `feedbackState.isDimmingActive`, без дополнительного старого порога дефицита 45%.
- Пауза, потеря контакта/потока, выключение оверлея и восстановление внимания
  снимают эффект; артефакт замораживает анимацию.
- Настоящий радиус шейдера регулируется в UI: **0–8 логических px**,
  исходное значение настройки делится на четыре; 0 отключает обычный эффект.
- Превью действует три секунды независимо от нулевых обновлений телеметрии.
- Старые полноэкранные Linux-окна скрываются, когда GPU-бэкенд берёт визуальную
  обратную связь на себя. При его отказе обычные визуальные кадры восстанавливаются.
- Ограниченный same-user Unix socket связывает Rust и рендерер; heartbeat,
  таймауты и watchdog не дают эффекту зависнуть после потери управления.
- Автоматически запущенный X11-helper получает Linux parent-death signal:
  он не остаётся фоновым процессом после завершения приложения.

Визуальная часть адаптирована из ZIP: диагональное появление частиц, начало
размытия около 3,08 с, ambient-фаза с 4,16 с, отталкивание курсором и возврат
на пружинах. Это не обещание пиксельного совпадения с HTML-демо.

Тест проверяет не только исчезновение резких границ, но и сохранение яркости:
чёрный экран больше не может выдать себя за «успешный блюр». При разработке
именно это обнаружило ошибку неполной текстуры KWin. Исправлено применением
отложенных параметров `GLTexture::bind()` и изоляцией sampler/GL state.

Ввод проверяется XTest-событиями, доставленными настоящему нижележащему
окну **пока эффект активен**, а не заглушкой IPC. До проверки эффекта
обязательно подтверждается, что именно Fly управляет тестовыми окнами.

| Команда | Итог |
|---|---|
| `cmake --build native/build` | KWin-плагин, X11-helper и тесты собраны; C++ с `-Wall -Wextra -Werror` |
| `python3 scripts/linux/test-native.py` | GPU blur, реакция на радиус, защита 5824 пикселей; физика/заморозка частиц; X11-интеграция |
| `FOCUSGLASS_TEST_RUST=1 python3 scripts/linux/test-kwin.py` | Настоящий KWin-плагин + production Rust worker: превью и очистка устаревшей телеметрии проходят |
| `FOCUSGLASS_TEST_RUST=1 FOCUSGLASS_TEST_FLY=1 python3 scripts/linux/test-native.py` | Fly-интеграция + production Rust worker проходят; helper завершился вместе с контроллером |
| `npm test` | Все 25 файлов наборов проходят, включая новый regression-тест восстановления legacy-визуализации |
| `npm run build` | TypeScript и Vite production bundle проходят |
| `npm run desktop:build:binary` | Linux release-приложение собрано: `src-tauri/target/release/focusglass`; установочные пакеты не собирались |
| `cargo test` | 76 passed, 0 failed, 3 ignored; native ignored-тест отдельно выполнен в KWin и Fly |
| `cargo clippy --all-targets -- -D warnings` | Не проходит из-за существующих Linux unused/dead-code в неизменённых `screen_blur.rs` и `distraction.rs` |
| `DESTDIR=… cmake --install native/build` | Staging проверен: `usr/lib/qt6/plugins/kwin/effects/plugins/focusglass.so` и `usr/bin/focusglass-x11` |

Полный прогон не означает ручную приёмку GUI на всех устройствах.
Смешанный DPI, повёрнутые/несколько мониторов, protected video, autohide-панели
и целевая Astra SE требуют отдельного тестирования. Аппаратный FPS/CPU/GPU
бенчмарк не заявляется: shader-тест выполнялся на llvmpipe.
