# Размытие Linux: GPU-бэкенды и резервный Wayland

Основная новая реализация для KDE/Wayland и X11:
[сборка, установка, устройство и изолированные тесты](../native/README.md).
KWin-плагин и XComposite-helper используют общий GPU-рендерер с регулируемым
радиусом и частицами; окна управления/HUD и доки исключаются.

Ниже описан **только резервный layer-shell-бэкенд**, который выбирается,
если нативный KWin-плагин не установлен. Его ограничения (нерегулируемый радиус,
возможное размытие HUD) не относятся к GPU-бэкендам.

Ветка: `feature/linux-liquid-glass-blur`.

## Включение

```bash
npm run desktop:dev
```

В настройках выберите режим `threshold_blur` («Блюр по порогу · Wayland»).
В Linux используется `feedbackState.isDimmingActive` и
`feedbackState.overlayOpacity`: эффект включается при падении сглаженной метрики
ниже пользовательского порога. Дополнительный дефицит 45% из прежней политики
карточки «Пауза» больше не блокирует нативный Linux-блюр. Математика старого
затемнения и Windows-политика не изменены.

В Wayland бэкенд запускается автоматически. Для явного отключения:
`FOCUSGLASS_WAYLAND_BLUR=0 npm run desktop:dev`. Значение `1` по-прежнему
поддерживается для принудительной попытки подключения. Windows-код и существующие
Linux-окна затемнения не заменяются. В браузере (`npm run dev`) размыть
рабочий стол нельзя; интерфейс теперь явно сообщает об этом.

В настройках есть панель статуса Linux-блюра и кнопка «Проверить блюр · 3 секунды».
Проверка независима от ЭЭГ и паузы и отключается по фиксированному таймеру.
Это позволяет отличить проблему порога от отсутствия поддержки композитора.
Статус «Слой размытия включён» означает наличие нативных поверхностей,
а не независимую проверку визуального результата.

В обычном режиме порог должен быть **выше текущего внимания**, чтобы вызвать
эффект: например, внимание 55%, порог 60%. Порог 10% при внимании 55%
не вызывает эффект. При включённой инверсии направление сравнения обратное.

Требования:

- Linux, доступное Wayland-соединение;
- `zwlr_layer_shell_v1`;
- `ext_background_effect_manager_v1` с capability `blur`;
- Rust >= 1.86 для сборки новых Wayland-зависимостей.

Проверяется наличие протоколов, а не имя рабочего окружения. Старые KDE,
X11 и Astra/Fly этим бэкендом не поддерживаются. GNOME не является целевой
платформой: поддержка background-effect без layer-shell недостаточна.
При отсутствии протоколов или ошибке соединения остаётся прежнее затемнение.
Запрос привилегий захвата экрана не нужен.

## Что реализовано

- Отдельное Wayland-соединение и поток, не меняющий GTK/WebView существующих окон.
- Нативная поверхность на каждый `wl_output`, слой `overlay`, все четыре якоря.
- `exclusive_zone = 0`: запрашивает рабочую область с учётом места, зарезервированного
  панелями/доками; сам ничего не резервирует. Панель с auto-hide, не резервирующая
  место, этим способом не исключается. Соблюдение рабочей области зависит от
  композитора.
- Пустая input region и `keyboard_interactivity = none`: не принимает мышь,
  touch или клавиатурный фокус. Ввод не пересылается искусственно.
- Реальное размытие фона через `ext-background-effect-v1`; слабый нейтральный
  полупрозрачный оттенок — обычный premultiplied ARGB SHM-буфер.
- На статичном экране буфер не перерисовывается; пересоздаётся при новом размере.
  Горячее подключение/отключение мониторов обрабатывается через registry.
- Включение при положительном запросе и активной обратной связи, без второго
  скрытого порога 4 px. Радиус не управляет силой эффекта композитора.
- Пауза, потеря контакта/потока, выключение оверлея и возврат внимания
  отключают новый слой. При артефакте сохраняется рассчитанное движком состояние.
- Heartbeat каждые 50 мс, latest-value mailbox без очереди устаревших кадров.
  При отсутствии heartbeat 2 секунды поверхности уничтожаются
  (если композитор отвечает); при выходе/разрыве соединения исчезают.
- `get_linux_blur_status` возвращает `linux`, `enabled`, `available`, `requested`,
  `active`, `mappedOutputs`, `message`; панель настроек обновляет статус каждые 500 мс;
  диагностические сообщения имеют префикс `[FocusGlass Wayland blur]`.

`fullscreen_dim`, `vignette_blur` и `distractors` новый бэкенд не включает:
полноэкранный эффект не должен превращать виньетку с чётким центром в сплошной
блюр или подменять размытие отдельных окон.

## Чего эта реализация НЕ обещает

**Это compositor blur, не shader-controlled Liquid Glass.** Общий протокол
задаёт только область, не радиус, ядро, насыщенность или преломление.
Значение `blurPx` здесь определяет включение/выключение, но не силу размытия.
Плавного изменения радиуса и гарантии «нечитаемости» текста нет: результат
зависит от настроек и реализации композитора. Стеклянный оттенок не означает
реализацию оптических эффектов Apple.

Layer-shell не даёт доступ к пикселям под поверхностью. Для нашего wgpu-шейдера,
самостоятельно размывающего/преломляющего фон, нужен отдельный источник чистого
фона. ScreenCast Portal не предоставляет стандартного исключения нашего оверлея:
захват итогового экрана создаёт рекурсию. Такой fallback намеренно не добавлен.

Нативный слой выше обычных GTK-окон: существующее затемнение, его карточки и HUD
тоже могут попасть под размытие. Их код не изменён; сохранение резкости HUD
потребует переноса его на отдельную layer-shell-поверхность над слоем блюра.
Порядок относительно других overlay-поверхностей определяет композитор.
Покрытие lock screen и других защищённых поверхностей не предполагается.

Размытие выбранных чужих окон — отдельная задача: прямоугольную blur region
задать можно, но общего layer-shell/background-effect API для перечисления,
геометрии и перекрытий чужих окон нет.

## Проверки

```bash
npm test
npx --no-install tsc --noEmit
cd src-tauri
cargo test
# Явно запускаемый smoke-test: кратко создаёт/удаляет сквозные поверхности.
cargo test wayland_smoke_maps_and_clears_all_outputs -- --ignored --nocapture
# Проверка реального worker/IPC-target пути: показывает слой 3 секунды.
cargo test wayland_worker_preview_expires_without_telemetry -- --ignored --nocapture
```

Smoke-test проверяет принятие протокольных запросов, configure, создание буферов
на всех выходах и повторное включение/выключение. Он не доказывает визуальное
качество или доставку физических нажатий другим программам.

При разработке прошли `npm test` (25 файлов), `npm run build`, `cargo test`
и явный Wayland smoke-test в доступной KDE-сессии. Проверка
`cargo clippy --all-targets -- -D warnings` блокируется существующими Linux-warning
в неизменённых `screen_blur.rs` и `distraction.rs`; исправление Windows-модулей
не включено в эту фичу. Проверка форматирования всего Rust-дерева также
обнаруживает прежние расхождения; новый `linux_blur.rs` отформатирован rustfmt.

Ручная приёмка:

1. Включить эффект, печатать и выделять текст в другом приложении, прокручивать
   и перетаскивать его окно; фокус не должен переходить в FocusGlass.
2. Проверить основной, дополнительный, повёрнутый и дробно масштабированный экран.
3. Проверить очистку после паузы, потери контакта, остановки приложения и возврата
   внимания; убедиться, что режим обычного затемнения остался прежним.
4. Проверить сообщения о неподдерживаемом протоколе и отсутствие чёрного экрана.
5. Оценить читаемость текста и силу эффекта с настройками конкретного композитора.
